## 3. Play Consoleでの作業

### 3-1. アプリの作成

- デフォルトの言語: 日本語（ja-JP）
- アプリかゲームか: ゲーム ／ 無料か有料か: 無料（無料で公開すると、後から有料にはできない）

### 3-2. テスト → 製品版の順番（アカウントの種類で変わる）
Play Consoleの「設定 → デベロッパー アカウント → アカウントの詳細」で種類を確認する。

- **組織アカウント**: クローズドテストの義務はない。内部テストで動作を確認してから、製品版のリリースを作成して審査に出す
- **個人アカウント**（2023年11月以降に作成）: 製品版の前に、**12人以上のテスターが14日間続けて**参加するクローズドテストが必要。その後ダッシュボードから製品版へのアクセスを申請する。正確な条件はダッシュボードの表示に従う

1. **内部テスト**（最大100人、審査なしですぐ配信）: AABをアップロードし、自分の端末で動作確認する
2. **クローズドテスト**（個人アカウントの場合のみ）: 同じAABをテスターに配信して14日間待つ
3. **製品版**: 同じAABを「ライブラリから追加」してリリースを作り、審査に送信する。審査は通常数日〜1週間

AABは1回アップロードすれば、トラックの間で使い回せる。同じversionCodeを2回アップロードすることはできない。

### 3-4. アプリのコンテンツ（申告）
現在のv1.6.0の実装に合わせた回答。広告を入れるときは変更する（末尾）。

| 項目 | 回答 |
| --- | --- |
| プライバシーポリシー | 上のURL |
| 広告 | **いいえ**（含まない） |
| アプリのアクセス権 | 特別なアクセス権は不要（ログインなし。全機能をすぐ使える） |
| コンテンツのレーティング | 下の「レーティング質問票」 |
| ターゲットユーザー | **13歳以上**（13〜15、16〜17、18以上）。13歳未満は選ばない。13歳未満を含めると「ファミリー向けポリシー」の対象になり、後から入れる広告の設定にも制約がかかる。「子どもの興味を引く可能性」は、内容（アイドル現場の警備）からして「いいえ」が妥当 |
| データセーフティ | データの収集: **なし** ／ データの共有: **なし**。理由はすぐ下 |
| 政府機関のアプリ／金融機能／健康 | いずれも該当しない |
| ニュースアプリ | いいえ |

**データセーフティの根拠:** 記録はすべて端末内（localStorage）だけに保存し、外部へは送らない。「結果を報告」は、利用者が自分で選んだアプリへ、AndroidのOSの共有メニューで文章を渡すだけ。こうした利用者自身の操作による受け渡しは、Googleの定義では「共有」に当たらない。分析・クラッシュ報告・広告のSDKは入っていない。アカウントが無いので、データ削除の窓口も不要。

**レーティング質問票（IARC）**: カテゴリは「ゲーム」。以下は実装内容に基づく目安。最終的な回答は内容を見て判断する。
- 流血・武器・性的表現・薬物・飲酒・喫煙・ギャンブル・暴言: なし
- 暴力: 警備員がタップで違反者を退場させる。モッシュはファン同士の接近と衝突で、負傷や流血の表現はない
- ユーザー同士の交流・チャット: なし（シェアは固定の文章をOSの共有メニューに渡すだけ）
- 位置情報の共有: なし ／ デジタル商品の購入: なし

## 4. 実機で見る点（内部テスト）
- 起動 → タイトル → 現場選択 → 60秒プレイ → 結果まで通しで動く
- 音あり／音なし。縦向き固定（端末を横にしても回転しない）
- Androidの戻る操作（`ANDROID_BACK_QA.md`）。プレイ中にホームへ出て戻ると一時停止している
- 「結果を報告」でAndroidの共有メニューが開き、LINEやXに文章を渡せる
- アプリを終了して起動し直しても、ベスト記録と解禁状況が残っている
- 機内モード（オフライン）でも、ドットフォントと画像が表示される

注意: 実機確認用APKと、Playから入れたアプリは署名が違うため、上書きインストールできない。Playから入れる前に、手動で入れたAPKをアンインストールする（アンインストールすると記録も消える）。デバッグAPKも同じ。

## 5. 次のバージョンを出すとき
- `android/app/build.gradle` の `versionCode` を必ず1以上増やす（例: 1→2）。`versionName` は `package.json` の `version` と一致させる（`verify:android` が照合する）
- ビルド: `npm run build:android:release`（Windowsの場合、PowerShellで先に `$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"` を設定）
- 出力: `android/app/build/outputs/bundle/release/app-release.aab`
- `android/keystore.properties` が無いと、署名なしのAABは作らずエラーで止まる

## 6. 広告（AdMob）を後から入れるとき
今回は広告なしで審査・公開する（2026-10-29 オーナー決定。iOSも同じ）。AdMobに登録したら、以下を**1つの新しいバージョン**（例: 1.7.0 / versionCode 2）にまとめる。

1. AdMobでアプリを登録し、Play Storeの掲載と紐付ける。本番のアプリIDと広告ユニットIDを発行する
2. PR #17（下書き）のテスト用IDを本番IDに差し替え、最新のmainに合わせてからマージする。IDの取り扱いはPR #17の説明に従う
3. 同意メッセージ: AdMobの「プライバシーとメッセージ」でGDPR向けの同意メッセージ（UMP）を設定する。iOSのトラッキング許可（ATT）はPR #17に入っている
4. **app-ads.txt**: AdMobはデベロッパーのウェブサイトの**ドメイン直下**（`https://ドメイン/app-ads.txt`）を見に行く。今のサイト `kmc48.github.io/dol-genba-security/` はサブフォルダなので、そのままでは置けない。`KMC48.github.io` という名前のリポジトリを作ってルートに置くか、独自ドメインを用意する。Play Consoleの「ウェブサイト」欄もそのドメインに合わせる
5. Play Consoleの申告を更新する:
   - 広告: **はい**
   - データセーフティ: AdMob SDKが収集・共有するデータ（デバイスなどのID、アプリの操作、診断情報など。目的は広告・分析・不正防止）を、Googleが公開しているAdMobのデータ開示ガイドに沿って申告する
   - 広告IDの申告: 使用する（AdMob SDKが `AD_ID` 権限を自動で追加する）
6. プライバシーポリシーの「広告、アクセス解析…は利用していません」を書き換え、広告配信のために収集する情報と、Googleのポリシーへのリンクを追加する。ストアの説明文に広告について書いていれば、それも直す
7. versionCodeを上げてAABを作り、内部テスト → 製品版の順で更新する
